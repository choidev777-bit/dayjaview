## 1. 제품 정의

DAYJAVIEW는 **장중 강해지는 국내 주식 테마를 수초 단위로 발견하고, 현재 움직임·확산도·근거가 확인된 상승 이유를 보여준 뒤, 의미상 관련된 과거 사건과 당시의 실제 결과를 연결하는 분석 서비스**다.

제품은 다음 질문에 순서대로 답한다.

1. 지금 어떤 테마가 강한가?
2. 한 종목만 움직이는가, 관련주 전반으로 확산되는가?
3. 현재 주도 종목은 무엇인가?
4. 왜 움직이는 것으로 확인됐으며 근거 상태는 무엇인가?
5. 오늘과 의미상 비슷했던 과거 사건은 무엇인가?
6. 그 사건 당시 주도주들은 이후 실제로 어떻게 움직였는가?

DAYJAVIEW는 사용자의 판단 자료를 구조화한다. 매수·매도 결정이나 미래 수익을 대신 판단하지 않는다.

## 2. 현재까지 검증된 사실

### 2.1 과거 유사사례 엔진 v1 기준선

[과거 유사사례 매칭 엔진 연구 보고서](./DAY-JA-VIEW_엔진_research_report.md)와 [모델 카드](./DAY-JA-VIEW_엔진_model_card.md)를 현재 기준선의 검증 근거로 사용한다. 이 결과는 문자 n-gram 기반 M-TXT v1과 당시 데이터·라벨·프로토콜에 한정되며, 최종 제품 검색기가 확정됐다는 뜻이 아니다.

| 확인된 결과 | 제품 반영 |
|---|---|
| M-TXT 검색은 관련성 평가에서 기준 모델보다 우수했음 | 관련 과거 사례 검색과 설명 태그에 사용 |
| v1 이웃 통계는 T+1 방향에서 기저율을 개선하지 못함 | 상승확률·방향예측·추천에 사용하지 않음 |
| 이웃 결과 구간은 실제 변동을 과소포착함 | 예측구간으로 표현하지 않음 |
| 관련성 라벨이 1인 검수에 의존함 | 수치 유사도와 보정되지 않은 유사도 밴드 미노출 |
| 엄격 outcome은 당시 주도주가 존재하는 2022년 이후 사건 중심임 | 오래된 사례 누락과 표본 범위를 사용자에게 고지 |

현재 v1 기준선의 확인된 가치는 다음으로 한정한다.

> 관련 과거 사례 검색 + 당시 실제 결과의 정직한 요약

다음 표현은 검증 결과와 맞지 않는다.

- 다음날 상승 가능성이 높다
- 과거 적중률이 높다
- 유사사례 기반 예상 수익률
- 80% 예측구간

### 2.2 온톨로지 구축 후 재검증

사건 온톨로지를 구축한 뒤 과거 유사사례 검색을 다시 평가한다. 이 단계는 기능 개선 선택사항이 아니라 사용자 노출 전 품질 게이트다.

비교 대상:

1. 현재 M-TXT v1 기준선
2. 온톨로지 구조 매칭
3. M-TXT와 온톨로지의 혼합 검색·재정렬

온톨로지는 최소한 사건 주체, 행동·촉매 유형, 진행 단계, 지역, 수혜 구조, 공식성, 신규성 표현을 버전된 통제어휘로 다룬다. 실제 데이터 감사를 거치기 전에 세부 분류를 수익률 결과에 맞춰 확정하지 않는다.

재검증 규칙:

- 검색 관련성과 결과 예측력을 별도 축으로 평가한다.
- 관련성은 2인 이상 블라인드 검수로 P@5, nDCG@5, 무관 사례 비율을 비교한다.
- 온톨로지 또는 혼합 방식은 M-TXT 기준선보다 관련성을 개선하거나, 통계적으로 동률이면서 설명·운영성이 명확히 좋아야 채택한다.
- T+1·T+5·T+20 결과는 검색 선택 완료 후 붙이며 검색 정답으로 사용하지 않는다.
- 방향 예측은 Brier score·교정·강한 비예측 기준선을 별도로 통과하기 전까지 계속 금지한다.
- 기존 2026-01-01~2026-08-11 봉인 구간은 새 모델의 최종 채택 근거로 재사용하지 않는다.
- 온톨로지·혼합 후보를 고정한 뒤 2026-09 이후의 새로운 미사용 봉인 구간에서 한 번 평가한다.
- 검색 방식이 바뀌면 새 엔진 버전과 데이터·온톨로지 버전을 발급하고 v1 결과를 덮어쓰지 않는다.

재검증 전 v1은 내부 기준선과 제한된 파일럿에만 사용할 수 있다. 일반 사용자용 유사사례 화면은 이 게이트를 통과한 엔진 버전을 사용해야 한다.

### 2.3 아직 검증된 제품 기능이 아닌 항목

- 장중 실시간 테마 기능은 `구현 전 기획안` 상태다.
- 실시간 트리맵은 `구현 계획` 상태다.
- 과거 테마 반응 소재 TOP3는 `데이터 감사 전 기능 정의안` 상태다.
- 조건부 지속성 예측 v2는 별도 연구이며 사용자 기능이 아니다.

문서가 존재한다는 사실만으로 기능 구현이나 성능이 완료된 것으로 표시하지 않는다.

## 3. 대상 사용자와 핵심 작업

### 3.1 핵심 사용자

국내 주식시장에서 뉴스와 거래대금을 중심으로 당일매매, 오버나잇, 단기 스윙, 주도주 매매를 수행하는 개인 투자자다.

기본 사용자는 다음 특성을 가진다.

- 종목보다 먼저 현재 시장의 강한 테마를 찾고 싶다.
- 뉴스 검색과 관련주 확인에 쓰는 시간을 줄이고 싶다.
- 한 종목의 급등과 테마 전체 확산을 구분하고 싶다.
- 과거 사건을 직접 찾아 차트를 하나씩 비교하는 과정을 줄이고 싶다.
- 불확실한 정보를 확정된 사실처럼 제공받고 싶지 않다.

### 3.2 핵심 사용자 작업

| 상황 | 사용자 작업 | 성공 기준 |
|---|---|---|
| 장중 탐색 | 현재 강한 테마 발견 | 홈 진입 후 5초 안에 상위 테마·주도주·확산 파악 |
| 원인 확인 | 상승 이유와 근거 상태 확인 | 확인 중·뉴스 추정·장후 확정을 구분 |
| 맥락 판단 | 현재 반응과 과거 관심 공백 파악 | 가격 위치와 관심 공백을 혼동하지 않음 |
| 과거 검증 | 의미상 관련된 사건과 실제 이후 결과 확인 | 사건별 근거와 표본 수를 함께 확인 |
| 장후 복기 | 장중 분류와 장후 확정 결과 비교 | 동일 Event ID로 이력 추적 |

## 4. 제품 원칙

### 4.1 발견과 설명을 분리한다

가격·거래량으로 무엇이 움직이는지 먼저 찾고, 저장된 뉴스 근거로 왜 움직이는지 나중에 확인한다. 뉴스가 없다는 이유로 시장 움직임을 숨기지 않고, 가격이 움직였다는 이유로 원인을 만들어내지 않는다.

### 4.2 현재 시장 영향과 확산을 함께 보여준다

현재 테마 반응은 Core 종목의 상한형 유동시가총액 가중 수익률로 보고, 확산은 Related를 포함한 유효 종목 중 상승 종목 수로 본다. 테마 수익률만 단독으로 제시하지 않는다.

### 4.3 과거 관측과 미래 예측을 분리한다

과거 사례의 T+1·T+5·T+20 값은 선택된 과거 사건에서 관측된 결과다. 이를 현재 사건의 확률, 예상 수익률 또는 추천으로 바꾸지 않는다.

### 4.4 미래 정보 누수를 허용하지 않는다

유사사례는 사건 당시 알 수 있던 정보만으로 선택한다. 미래 가격 결과는 사례 선택이 끝난 뒤 결과표로 결합한다. 현재 관련주를 과거 사건에 소급하지 않는다.

### 4.5 모르는 상태를 제품 상태로 취급한다

`상승 이유 확인 중`, `데이터 갱신 중`, `표본 부족`, `수신 지연`, `장후 미확정`을 정상 상태로 설계한다. 결측을 0으로 표시하거나 확정 문장으로 채우지 않는다.

### 4.6 장중과 장후의 사건 정체성을 유지한다

장후 인포스탁 분류가 장중 추정과 달라도 장중 기록을 삭제하지 않는다. 같은 Event ID를 유지하고 분류 변경 이력과 근거를 보존한다.

### 4.7 출처와 권리를 우선한다

허용된 경로로 수집한 데이터만 사용한다. 뉴스 전문을 무단 재배포하지 않으며 자체 요약, 매체, 발행 시각, 원문 링크를 제공한다.

## 5. 제품 목표와 비목표

### 5.1 목표

1. 시장 전체 후보를 넓게 감지하고 활성 테마를 수초 단위로 갱신한다.
2. 테마 강도와 확산, 현재 주도주를 한 화면에서 이해하게 한다.
3. 상승 이유의 확인 수준과 출처를 명확히 보여준다.
4. 관련 과거 사건을 빠르게 찾고 실제 결과를 비교하게 한다.
5. 데이터 시점·표본 수·결측·분류 변경을 감사 가능하게 유지한다.
6. 장중 탐지와 장후 확정 결과를 연결해 탐지·분류 품질을 개선한다.
7. 저장된 사건 기록을 자연어 질문으로 조회하게 하되, 모든 답변에 표본 수와 근거 사건을 함께 제시한다.

### 5.2 비목표

- 자동매매 또는 주문 실행
- 증권계좌 연결, 보유종목·수익률·주문내역 관리
- 관심 항목의 이메일·SMS·Web Push 알림
- 종목 추천, 매수·매도 신호, 목표가 제공
- 현재 사건의 상승확률이나 예상 수익률 제공
- 모든 KRX 종목의 모든 체결을 한 세션에서 전수 분석한다는 보장
- 뉴스보다 항상 먼저 원인을 식별한다는 보장
- 신규 테마명을 가격만으로 즉시 확정
- 키움 테마 분류를 DAYJAVIEW 기준 taxonomy로 사용
- MVP에서 공시·DART, 텔레그램, NXT·SOR 통합
- 연구 중인 v2 예측 결과의 사용자 노출

## 6. 제품 범위

### 6.1 핵심 MVP

| 기능 | 사용자 가치 | 상태 |
|---|---|---|
| Google 로그인과 접근 제어 | 승인된 사용자만 제품 데이터에 접근 | 구현 대상 |
| 관심·저장 | 테마·종목·현재/과거 이벤트를 계정에 저장하고 다시 확인 | 구현 대상 |
| 오늘의 강한 테마 | 현재 순위·주도주·확산·이유를 빠르게 파악 | 구현 대상 |
| 실시간 테마 인사이트 | 활성 테마의 상승률 분포를 트리맵으로 탐색 | 구현 대상 |
| 테마 상세 요약 | 오늘의 소재, 현재 반응, 관심 공백, 주도 종목 확인 | 구현 대상 |
| 과거 유사사례 | 관련 사건과 당시 주도주 T+1·T+5·T+20 관측값 확인 | 온톨로지 구축·새 봉인 구간 재검증 후 사용자 노출 |
| 과거 이벤트 상세 | 왜 비슷한지와 사건별 실제 결과 확인 | 유사사례 재검증 게이트에 종속 |
| 장중→장후 연속성 | 장후 인포스탁 확정과 분류 변경 이력 유지 | 구현 대상 |

### 6.2 게이트를 통과해야 포함되는 확장 기능

#### 과거 테마 반응 소재 TOP3

다음 조건을 모두 통과한 뒤 테마 상세 요약에 포함한다.

- 인포스탁 원본과 당시 주도주 데이터 감사
- 소재 유형 분류의 재현성 검증
- 최소 표본과 안정성 기준 확정
- 원시 반응과 시장 대비 반응 비교
- 화면 문구가 미래 예측으로 오인되지 않는지 확인

통과 전에는 목업 수치나 임의 TOP3를 제품 데이터로 노출하지 않는다.

#### 자연어 리서치 질의

`리서치` 탭에서 저장된 사건 기록을 자연어로 조회한다. 답변 범위는 확보된 데이터에 종속되며 단계적으로 넓힌다.

- **1단계(선행 없음)**: 현재 시장·구조·근거 질문. "지금 뭐가 오르나", "이 테마가 왜 오르나", "이 종목은 어느 테마인가". FR-1~FR-4가 이미 계산하는 값을 질의 형태로 노출하는 것이다.
- **2단계(선행: E-16 과거 주가 + E-17 온톨로지)**: 과거 집계 질문. "이 소재에 과거 어떤 테마가 반응했나", "몇 번 있었고 그때 반응은 어땠나".
- **3단계(선행: E-19 통과)**: 유사사례 질문. 2인 블라인드 평가 전에는 잠근다.

다음 조건을 모두 지킨다.

- 답변의 모든 수치는 결정론적 계산 결과이며 LLM은 문장 표현만 담당한다. LLM이 수치·순위·확률을 생성하지 않는다.
- 모든 답변에 표본 수와 근거 사건 목록을 함께 표시한다. 근거를 제시할 수 없으면 답하지 않는다.
- 질문 해석 결과(테마·기간·소재 유형)를 사용자에게 보여주고 수정 가능하게 한다.
- 답할 수 없는 경우를 **기록 없음 / 질문 해석 실패 / 제품 범위 밖** 세 가지로 구분해 제시한다.
- 미래 예측·매매 판단 요구는 5.2 비목표에 따라 거절하며, 우회 표현으로도 제공하지 않는다.
- 답변 문구는 과거 관측 시제로 고정한다(4.3 원칙).

#### 조건부 지속성 예측 v2

별도 연구 게이트를 모두 통과하고 새 봉인 데이터에서 재현되기 전까지 제품 범위 밖이다. 연구가 실패하면 방향 예측을 제품에서 제외한다. 이 결정은 온톨로지 재검증을 통과한 검색기의 과거 관측 요약 제공 여부와 별개다.

### 6.3 이번 문서에서 확정하지 않는 보조 기능

테마 전체 목록과 글로벌 검색은 핵심 여정을 지원하는 후속 범위다. 관심·저장 화면과 내부 운영자 콘솔은 구현 대상이며 알림 기능은 제품 범위에서 제외한다. 운영자 콘솔은 일반 사용자 제품 화면·내비게이션·API와 완전히 분리하며 일반 사용자 MVP 화면으로 취급하지 않는다.

## 7. 핵심 사용자 여정

모든 제품 여정은 Google 로그인 후 시작한다. 비로그인 사용자는 로그인 화면만 볼 수 있으며 오늘·인사이트·테마·뉴스·유사사례 데이터는 받지 않는다. OAuth callback·logout과 최소 health check만 예외다.

### 7.1 장중 발견

```text
오늘
→ 강한 테마 카드 확인
→ 주도주·확산·이유 상태 확인
→ 테마 상세 진입
→ 현재 맥락과 과거 관측 확인
```

### 7.2 시장 지형 탐색

```text
인사이트
→ 상승률 기준 실시간 트리맵 확인
→ 관심 테마 타일 선택
→ 동일 Event ID의 테마 상세 진입
```

### 7.3 과거 사례 검증

```text
테마 상세
→ 유사사례 표본 수와 중앙값 확인
→ 왜 비슷한지 근거 태그 확인
→ 과거 이벤트 상세
→ 당시 주도주와 사건별 실제 결과 확인
```

### 7.4 장후 복기

```text
장중 이벤트
→ 장 마감
→ 인포스탁 업데이트 반영
→ 같은 Event ID에 확정 분류 저장
→ 장중 분류와 변경 이력 확인
```

### 7.5 관심 항목 다시 보기

```text
테마·종목·현재 또는 과거 이벤트에서 저장
→ 관심 화면에서 유형별 확인
→ 활성 상태와 최근 변경 확인
→ 원래 상세 화면으로 이동하거나 저장 해제
```

## 8. 기능 요구사항

### FR-1. 실시간 후보 발견과 테마 활성화

- 시장 전체 후보 발견은 키움 조건검색과 순위·급등락 조회를 조합한다.
- 선택된 후보와 활성 테마 구성종목만 0B 체결로 정밀 추적한다.
- 한 세션의 정밀 구독은 최대 200종목 제약을 전제로 우선순위를 관리한다.
- 체결이 발생한 종목과 연결된 테마만 증분 갱신한다.
- 활성화·약화·종료에는 hysteresis를 적용해 카드가 짧은 틱 변화로 반복 출입하지 않게 한다.
- 핵심 화면은 정상 상태에서 서버 수신 후 2~3초 안에 갱신하는 것을 목표로 한다.

세부 구현 계약은 [realtime_theme_feature_spec.md](./realtime_theme_feature_spec.md)를 따른다.

### FR-2. 현재 테마 순위와 카드

- 홈 정렬은 채택된 복합 순위 점수를 사용하되 내부 점수를 노출하지 않는다.
- 카드에는 테마명, 순위, 상태 배지, 근거 상태가 포함된 상승 이유, 대표 주도주, 테마 수익률, 상승 종목 수, 마지막 갱신 시각을 제공한다.
- 테마 수익률을 표시할 때 상승 종목 수를 함께 표시한다.
- Coverage가 부족하면 순위를 강제로 계산하지 않고 `데이터 갱신 중`으로 표시한다.
- 이유가 확인되지 않았으면 `상승 이유 확인 중`으로 표시한다.

### FR-3. 상승 이유와 뉴스 근거

- 특징주 뉴스는 테마 탐지와 독립적으로 장중 계속 수집한다.
- 저장된 뉴스와 테마를 양방향으로 매칭한다.
- 로컬 근거가 없고 호출 조건을 충족할 때만 서버가 보완 검색한다.
- LLM은 인터넷을 검색하지 않으며, 관련성 기준을 통과한 기사에서 구조화·자체 요약만 수행한다.
- 근거가 없으면 LLM을 호출하지 않는다.
- 사용자에게 매체, 발행 시각, 원문 링크, 근거 상태를 제공한다.
- 장후에는 인포스탁 기준 확정 상태와 변경 이력을 연결한다.

### FR-4. 테마 상세

테마 상세 요약은 다음 순서를 기본으로 한다.

1. 테마명과 현재 테마 수익률·확산
2. 오늘 부각된 이유와 근거 상태
3. 관심 공백과 오늘 거래 관심
4. 현재 시장 순위와 확산 상태
5. 현재 주도 종목 상위 3개
6. 게이트 통과 시 과거 테마 반응 소재 TOP3
7. 온톨로지 재검증 통과 시 과거 유사사례 요약
8. 온톨로지 재검증 통과 시 가장 관련된 과거 사례

정확한 화면 규칙은 [screen_spec.md](./screen_spec.md)를 따른다.

### FR-5. 과거 유사사례 검색과 결과 요약

- 현재 사건과 같은 테마의 과거 사건 중 원인문과 온톨로지 사건 구조의 관련성을 기준으로 후보를 찾는다.
- M-TXT, K=20, `leader_ew_v1`은 재검증 비교를 위한 v1 기준선으로 보존한다.
- 사용자 노출 버전은 온톨로지 구조 매칭과 혼합 후보를 비교하고 새 봉인 구간을 통과한 뒤 확정한다.
- 상위 사례에는 사건일, 요약, 왜 비슷한지에 대한 근거 태그, 당시 주도주 결과를 제공한다.
- 통계는 Top20의 유효 사건을 기준으로 T+1·T+5·T+20별 유효 표본 수, 상승 사건 수, 중앙 수익률을 제공한다.
- 화면 목록은 관련 사례 Top5를 우선 노출한다.
- 기간별 가격 존재 여부가 다르면 각 기간의 분모를 별도로 표시한다.
- 표본 부족, point-in-time 안전성, 누락 필드를 품질 상태로 반환한다.
- 현재 진행 중 사건은 자기 자신의 과거 후보에 포함하지 않는다.

### FR-6. 과거 이벤트 상세

- 사건일, 테마, 사건 요약을 표시한다.
- 수치 유사도 대신 공유 토큰 또는 구조 태그로 `왜 비슷한지` 설명한다.
- 당시 주도주 동일가중 바스켓의 T0·T+1·T+5·T+20 실제 결과를 표시한다.
- 종목별 결과는 당시 기록된 주도주만 사용한다.
- 가격 누락 또는 관찰 미완료 상태를 0%로 표시하지 않는다.
- 미래 결과가 사례 선택에 사용되지 않았음을 도움말에서 설명한다.

### FR-7. 실시간 테마 트리맵

- `인사이트` 화면에서 상승률 단일 지표를 사용하며 지표 토글을 두지 않는다.
- 상한형 유동시총 가중 수익률이 0% 초과이고 Core Coverage 기준을 통과한 ACTIVE·WEAKENING 테마 중 상위 12개를 표시한다.
- 면적과 색상은 동일한 `weightedReturn` 값에 의해 결정한다.
- 내부 복합 순위 점수나 랜덤값을 면적에 사용하지 않는다.
- 타일 선택 시 `themeId`와 `eventId`를 유지해 테마 상세로 이동한다.
- 지연 시 마지막 정상 화면을 유지하고, 결측이나 Coverage 미달을 0으로 만들지 않는다.
- 장 마감 시 최종 스냅샷을 고정하고 애니메이션을 중지한다.

세부 계약은 [realtime_theme_treemap_implementation_plan.md](./realtime_theme_treemap_implementation_plan.md)를 따른다.

### FR-8. 이벤트 수명주기와 감사 기록

- 이벤트에는 최초 탐지 시각, 소재 최초 확인 시각, 상태 변경, 주도주 변경, 사용한 뉴스 근거를 기록한다.
- 장중 임시 분류와 장후 확정 분류는 같은 Event ID를 사용한다.
- 분류 변경 시 이전 테마, 새 테마, 변경 주체, 시각, 사유를 보존한다.
- 데이터·모델·프롬프트·membership·baseline 버전을 재현 가능하게 저장한다.
- 원본 변경을 덮어쓰지 않고 관측 이력을 유지한다.

### FR-9. 사용자 관심·저장

- Google 계정별로 테마, 종목, 접근 가능한 현재·과거 이벤트를 저장·해제한다.
- 관심 화면은 테마·종목·이벤트를 구분하고 저장 시각, 현재 상태, 최근 변경을 제공한다.
- 저장 여부가 테마 순위·검색 점수·시장 계산이나 공용 cache를 바꾸지 않는다.
- 같은 사용자의 같은 대상을 중복 저장하지 않으며 저장·해제 요청은 재실행 가능해야 한다.
- 삭제·비활성·권한 제한 대상은 다른 대상으로 조용히 치환하지 않고 `사용 불가` 이유를 표시한다.
- 사용자는 자기 저장 데이터와 계정을 삭제할 수 있다.
- 알림·이메일·자동매매·증권계좌 연결은 제공하지 않는다.

### FR-10. 내부 운영자 콘솔

- 허용된 Google 계정의 `OPERATOR` 역할만 접근한다.
- 일반 사용자 내비게이션·검색·route 안내에 진입점을 노출하지 않고 직접 API 접근도 서버에서 `403`으로 거부한다.
- 키움·뉴스·인포스탁 수집 상태, 마지막 성공 시각, 실패 작업과 재시도·재개를 제공한다.
- 인포스탁 `AUTH_REQUIRED` 상태와 SSH tunnel 기반 수동 재인증 절차를 연결한다. 인증 UI를 public port로 노출하지 않는다.
- 장중·장후 불일치, 뉴스 근거, 미매칭 Event 검수 대기열을 제공한다.
- 분류 수정·병합·제외는 원본 덮어쓰기나 hard delete 대신 근거가 있는 revision으로 저장한다.
- 모든 운영자 command는 수행자·시각·대상·사유·이전/이후 상태를 감사 기록으로 남긴다.
- 기본 process·source 상태와 배포 버전을 표시하되 서버 shell, secret, cookie, token, 원문 credential은 표시하거나 수정하게 하지 않는다.

### FR-11. 자연어 리서치 질의

`리서치` 탭에서 제공한다. 단계별 범위와 게이트는 6.2 「자연어 리서치 질의」를 따른다.

- 질문을 **닫힌 질의 유형 집합**으로 분류하고 슬롯(테마·종목·기간·소재 유형·방향)을 채운다. 자유 형식 SQL 생성이나 문서 검색 기반 답변 생성을 사용하지 않는다.
- 슬롯 값은 알려진 식별자로만 해석한다. 해석되지 않으면 추측하지 않고 사용자에게 후보를 되묻는다.
- 해석 결과를 답변과 함께 표시하고 사용자가 고쳐 다시 질의할 수 있게 한다.
- 수치는 기존 계산 계약(9절)과 동일한 함수로 산출한다. 같은 질문은 같은 답을 재현한다.
- 답변은 한 문장 요약, 수치 요약(표본 수 필수), 근거 사건 목록, 제시하지 못한 항목의 사유로 구성한다.
- 근거 사건 목록의 항목에서 테마 상세·과거 이벤트 상세로 이동할 수 있어야 한다.
- 답할 수 없는 경우 사유를 **기록 없음 / 질문 해석 실패 / 제품 범위 밖**으로 구분한다.
- 질의·응답 내용을 사용자 행동 분석 목적으로 축적하지 않는다(5.2 비목표의 제품 analytics 제외 원칙). 운영자 콘솔에는 답변 실패 사유 집계만 노출한다.

## 9. 계산과 의미 계약

### 9.1 현재 테마 반응

| 값 | 계산 대상 | 의미 |
|---|---|---|
| 테마 수익률 | Core 종목, 전일 기준 상한형 유동시총 가중 | 시장가치 관점의 현재 반응 |
| 상승률 중앙값 | Related 포함 유효 구성종목 | 전형적인 관련주의 반응 |
| 상승 확산도 | Related 포함 상승 종목 수 / 유효 종목 수 | 움직임의 확산 범위 |
| 거래 관심 배수 | 동일 시각 과거 기준선 대비 누적 거래대금 | 평소 대비 거래 관심 |
| 관심 공백 | 이전 관심 구간 종료와 현재 구간 시작 사이 거래일 | 오랜 기간 시장 관심이 없었는지 |

관심 공백은 저가 상태나 가격 위치를 의미하지 않는다.

### 9.2 과거 사건 성과

| 값 | 계산 대상 | 의미 |
|---|---|---|
| 사건별 수익률 | 사건 당시 인포스탁 주도주 동일가중 바스켓 | 해당 사건에서 관측된 실제 결과 |
| 여러 사건의 대표값 | 유효 사건별 바스켓 수익률의 중앙값 | 표본의 중앙 관측값 |
| 상승 사건 수 | 바스켓 수익률이 0% 초과인 유효 사건 수 | 과거 표본의 관측 빈도 |

현재 테마의 시총 가중 방식과 과거 사건의 주도주 동일가중 방식은 목적이 다르므로 혼합하지 않는다.

- 장중 의사결정 시점보다 나중에 공개된 정보를 소급하지 않는다.
- 데이터 접근 권리와 이용약관을 확보하기 전 운영 수집을 시작하지 않는다.

## 14. 우선순위와 단계

### Phase 0. 기반과 권리

데이터 사용 권리, 인포스탁 DB, 가격·기준정보, 키움 PoC를 확정한다.

### Phase 1. 핵심 실시간 경험

기존 인포스탁 테마의 장중 탐지, 순위, 홈 카드, 테마 상세, 상태·Coverage를 구현한다.

### Phase 2. 근거 기반 상승 이유

특징주 뉴스 수집, 양방향 매칭, 근거 상태, 출처 상세, 장후 확정 연결을 구현한다.

### Phase 3. 과거 사례 경험

v1을 재현 가능한 기준선으로 유지하면서 사건 온톨로지를 구축한다. M-TXT·온톨로지·혼합 방식을 2인 관련성 평가와 새 봉인 구간에서 재검증한 뒤 채택 버전을 테마 상세와 과거 이벤트 상세에 연결한다.

### Phase 4. 인사이트와 신규 테마

실시간 트리맵, 미분류 동반 상승, 임시 명명, 운영자 병합·분리를 구현한다.

### Phase 5. 검증 후 확장

과거 테마 반응 소재 TOP3와 조건부 예측 연구 결과는 각 출시 게이트를 통과한 항목만 포함한다.

## 16. 제품 완료 정의

DAYJAVIEW의 핵심 제품 경험은 다음 조건을 모두 만족할 때 완료로 본다.

1. 실제 장중 체결로 기존 테마가 활성화되고 홈이 수초 단위로 갱신된다.
2. 사용자가 현재 테마 강도와 확산을 구분할 수 있다.
3. 상승 이유의 근거 상태와 출처가 표시되며 근거가 없을 때 생성하지 않는다.
4. 온톨로지 재검증 게이트를 통과한 검색기로 과거 유사사례와 당시 실제 결과를 확인할 수 있다.
5. 과거 관측값이 현재 사건의 예측이나 추천으로 표현되지 않는다.
6. 지연·결측·표본 부족·분류 미확정 상태가 정상적으로 표시된다.
7. 장중 이벤트와 장후 인포스탁 확정값이 같은 Event ID와 변경 이력으로 연결된다.
8. 데이터·모델·화면 문구가 각 출시 게이트와 자동·수동 검증을 통과한다.
9. 비로그인 요청에서 제품 데이터가 노출되지 않고 Google 로그인 후 원래 목적 화면으로 안전하게 복귀한다.
10. 관심 테마·종목·이벤트가 Google 계정에 저장·동기화되고 사용자가 저장 데이터와 계정을 삭제할 수 있다.
11. 운영자 콘솔이 일반 사용자에게 노출되지 않으며 모든 검수·수정 command가 감사 가능한 revision으로 남는다.

제품의 한 줄 원칙은 다음과 같다.

> 지금 시장에서 무엇이 왜 움직이는지 빠르게 보여주고, 관련된 과거를 정직하게 연결하되, 관측을 예측처럼 말하지 않는다.
