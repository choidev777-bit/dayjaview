## 1. 한 줄 정의

`과거 테마 반응 소재 TOP3`는 **인포스탁에 기록된 한 테마의 과거 사건을 소재 유형별로 묶고, 당시 주도주 바스켓의 당일 반응 중앙값이 컸던 소재 유형을 최대 3개 보여주는 기능**이다.

이 기능이 답하는 질문은 다음과 같다.

> 과거에 원전 테마가 크게 반응했던 날에는 주로 어떤 종류의 소재가 있었는가?

이 기능은 오늘 또는 미래의 수익률을 예측하지 않는다.

## 2. 제품 결정 요약

| 항목 | 결정 |
|---|---|
| 사용자용 기능명 | `과거 {테마명} 테마 반응 TOP3` |
| 비교 단위 | 개별 단어가 아닌 정규화된 `소재 유형` |
| 강함의 의미 | 과거 사건 당시 주도주 바스켓의 T-1 종가 대비 T0 종가 반응 |
| 대표 통계 | 소재 유형별 유효 사건의 당일 반응 중앙값 |
| 발생 횟수의 역할 | 최소 표본 필터와 보조 정보이며 순위의 주 기준은 아님 |
| LLM의 역할 | 과거 원인문에서 사건 구조와 소재 유형 후보 추출 |
| LLM이 하지 않는 일 | 소재 강도 점수 생성, 주가 원인 확정, 미래 수익 예측 |
| 온톨로지의 역할 | 서로 다른 표현을 같은 소재 유형으로 정규화 |
| 인포스탁의 역할 | 과거 테마 사건 원문과 당시 주도주를 제공하는 기준 원천 |
| 현재 상태 | 원천 데이터 미수집이므로 구현·노출 전 데이터 감사 필요 |

## 3. 기존 기능과의 차이

세 기능은 서로 다른 질문에 답한다.

| 기능 | 사용자 질문 | 비교 대상 |
|---|---|---|
| 오늘의 소재 | 오늘 이 테마는 왜 움직이는가? | 오늘의 뉴스·근거 |
| 과거 테마 반응 소재 TOP3 | 과거 이 테마가 크게 반응한 소재 유형은 무엇인가? | 해당 테마의 전체 과거 사건 |
| 과거 유사사례 | 오늘과 구조적으로 비슷했던 과거 사건은 언제인가? | 오늘 사건과 가까운 과거 사건 |

예를 들어 오늘 원전 테마의 소재가 `체코 원전 우선협상대상자 선정`이라면 다음처럼 역할이 나뉜다.

```text
오늘의 소재
체코 신규 원전 우선협상대상자 선정

과거 원전 테마 반응 TOP3
1. 해외 원전 수주 단계 진전
2. 국내 원전 확대·재가동 정책
3. SMR 투자·사업 협력

과거 유사사례
2024.07 체코 원전 최종후보 선정
2022.10 폴란드 원전 협력의향서 체결
```

TOP3는 오늘 사건과 비슷한 사례만 고르는 검색 기능이 아니다. 해당 테마의 과거 소재 지형을 요약하는 기능이다.

## 4. 해결하려는 사용자 문제

테마명만으로는 어떤 사건이 실제로 큰 반응과 함께 나타났는지 알기 어렵다.

예를 들어 `원전`에는 다음처럼 성격이 다른 소재가 함께 들어갈 수 있다.

- 해외 원전 수주와 계약 단계 진전
- 국내 신규 원전 건설 또는 재가동 정책
- SMR 투자와 기술 협력
- 원전 해체 사업
- 핵연료와 기자재 공급

사용자는 TOP3를 통해 다음을 빠르게 파악할 수 있어야 한다.

1. 이 테마의 과거 주요 촉매 유형은 무엇이었는가?
2. 그 유형은 과거 몇 번 관측됐는가?
3. 그때 테마 주도주들이 당일 어느 정도 반응했는가?
4. 오늘 소재가 그중 어떤 유형과 연결되는가?

## 5. 범위와 비범위

### 5.1 포함

- 테마별 과거 인포스탁 히스토리 원문 수집
- 과거 히스토리별 당시 주도주 보존
- 사건 중복 제거와 수정 이력 관리
- 과거 소재의 구조화 및 정규화
- 당시 주도주 바스켓의 T0 당일 반응 계산
- 소재 유형별 유효 표본 수와 중앙 반응 집계
- 테마별 최대 3개 소재 유형 노출
- 오늘 소재와 동일한 유형일 때 `오늘과 같은 유형` 표시
- 계산 기준, 표본 수, 데이터 한계 설명

### 5.2 제외

- `북한`, `수주`, `정책` 같은 단어 빈도 순위
- LLM이 주관적으로 생성한 `강도 92점`
- 특정 소재가 나오면 상승한다는 미래 예측
- 매수·매도 추천
- 오늘의 소재와 과거 TOP3를 같은 값으로 취급
- 현재 관련주 목록을 과거 사건의 주도주로 소급 적용
- 과거 수익률이 좋도록 소재 분류 기준을 사후 조정
- 데이터가 부족한데도 반드시 3개를 채워 표시

## 6. 핵심 용어와 의미 계약

### 6.1 사건

인포스탁 테마 히스토리의 한 기록을 정규화한 분석 단위다.

```text
2024-07-17
체코 신규 원전 사업 우선협상대상자로 한국수력원자력 선정
당시 주도주: A, B, C
```

같은 사건을 표현만 바꿔 여러 번 기록한 경우 하나의 중복 클러스터로 묶는다.

### 6.2 소재 유형

여러 과거 사건을 비교할 수 있도록 공통 구조로 묶은 상호 배타적 표시 단위다.

```text
원문 사건
체코 원전 최종후보 선정
폴란드 원전 협력의향서 체결
UAE 원전 추가 수주 기대

표시 소재 유형
해외 원전 수주 단계 진전
```

한 사건에는 여러 키워드가 있을 수 있지만 TOP3 집계에는 원칙적으로 `primary_catalyst_group` 하나만 사용한다. 이 규칙은 한 사건이 여러 유형의 표본 수를 동시에 부풀리는 것을 막는다.

### 6.3 당일 반응

사건 당시 인포스탁이 주도주로 기록한 종목들의 동일가중 바스켓 수익률이다.

```text
종목 당일 반응(i, e)
= 조정종가(i, T0) / 조정종가(i, T-1) - 1

사건 당일 반응(e)
= 당시 주도주들의 종목 당일 반응 단순평균
```

- `T-1`: 사건 직전 KRX 거래일
- `T0`: 사건이 가격에 처음 반영된 거래일
- 장 마감 후 공개가 확인된 사건은 다음 거래일을 T0로 사용
- 공개 시각을 확인할 수 없으면 `T0_TIME_UNKNOWN` 품질 플래그를 기록
- 액면분할·배당락 등 기업행위를 반영한 조정종가 사용

### 6.4 소재 유형의 대표 반응

동일 소재 유형에 속한 유효 사건들의 당일 반응 중앙값이다.

```text
소재 유형 대표 반응(g)
= median(사건 당일 반응(e)), e ∈ g
```

평균이 아니라 중앙값을 기본으로 사용하는 이유는 한 번의 상한가나 이상치가 순위를 지배하는 것을 줄이기 위해서다.

### 6.5 TOP3

최소 표본과 품질 기준을 통과한 소재 유형을 대표 반응 내림차순으로 정렬한 상위 최대 3개다.

`TOP3`는 다음 의미가 아니다.

- 앞으로 가장 많이 오를 소재
- 발생 가능성이 가장 높은 소재
- 뉴스 자체의 중요도
- 전체 시장에 미친 절대 영향

## 7. 사용자 화면

### 7.1 기본안

테마 상세 `요약` 탭에서 `오늘의 소재` 및 `현재 반응` 다음에 배치한다.

```text
과거 원전 테마 반응 TOP3
인포스탁 히스토리에 기록된 사례 기준

1  해외 원전 수주 단계 진전
   12건 · 당일 중앙 반응 +6.4%
   오늘과 같은 유형

2  국내 원전 확대·재가동 정책
   8건 · 당일 중앙 반응 +4.9%

3  SMR 투자·사업 협력
   7건 · 당일 중앙 반응 +3.8%

[계산 기준]
```

위 수치는 화면 구조를 설명하기 위한 예시이며 실제 값이 아니다.

### 7.2 상세 진입

각 소재 유형을 누르면 해당 집계에 포함된 사건 목록을 보여준다.

```text
해외 원전 수주 단계 진전

2024.07.17  체코 원전 우선협상대상자 선정   +8.1%
2022.10.31  폴란드 원전 협력의향서 체결      +5.4%
...

12건 중앙 반응 +6.4%
```

목록에는 사건일, 정규화 요약, 사건 당일 반응, 당시 주도주, 데이터 품질 상태를 제공한다.

### 7.3 계산 기준 설명

사용자에게 다음 내용을 확인할 수 있게 한다.

```text
과거 인포스탁 테마 히스토리에서 같은 유형의 소재를 묶고,
각 사건 당시 기록된 주도주의 전일 종가 대비 당일 종가 반응을 계산했습니다.
표시 값은 유효 사례의 중앙값이며 미래 수익률 예측이 아닙니다.
```

### 7.4 표본 부족

- 유효 소재 유형이 3개면 TOP3 표시
- 유효 소재 유형이 1~2개면 존재하는 항목만 표시하고 `TOP3`라는 표현은 사용하지 않음
- 유효 소재 유형이 0개면 숫자나 임의 분류를 만들지 않음

```text
과거 반응 소재
분석 가능한 과거 사례가 아직 부족해요
```

### 7.5 오늘과 같은 유형

오늘 사건과 과거 소재 그룹의 `primary_catalyst_group_id`가 같고 오늘 사건의 근거 상태가 기준을 통과한 경우에만 표시한다.

`오늘과 같은 유형`은 오늘도 과거와 같은 수익률이 나온다는 뜻이 아니다. 도움말에 이를 명시한다.

## 8. 사용자 표현 원칙

### 8.1 권장 표현

- `과거 원전 테마 반응 TOP3`
- `당일 중앙 반응 +6.4%`
- `과거 12건 기준`
- `오늘과 같은 유형`
- `분석 가능한 과거 사례 부족`

### 8.2 사용하지 않는 표현

- `가장 강력한 호재`
- `상승 가능성 높은 소재`
- `성공률 80%`
- `다음에도 오를 확률`
- `LLM 분석 강도 92점`
- `원전 테마를 움직인 원인`처럼 검증되지 않은 인과를 확정하는 표현

정확한 제품 의미는 **과거 기록에서 큰 당일 반응과 함께 나타난 소재 유형**이다.

## 9. 데이터 요구사항

### 9.1 인포스탁 원천 데이터

- 테마 ID와 테마명
- 히스토리 날짜
- 히스토리 전체 원문
- 주도주 목록을 제거한 사건 원인문
- 해당 시점의 인포스탁 주도주 이름과 종목코드
- 원본 URL 또는 원본 스냅샷
- 최초 관측 시각과 수정 이력
- 중복 여부를 판단할 원문 해시

기존 [인포스탁 DB 구현 계획서](./infostock_db_implementation_plan.md)의 `theme_history`와 `theme_history_leaders`를 원천으로 사용한다.

### 9.2 가격·시장 데이터

- KRX 거래일 달력
- 종목별 조정종가 T-1, T0
- 기업행위와 조정값 버전
- 종목별 KOSPI·KOSDAQ 소속 이력
- KOSPI·KOSDAQ 지수 T-1, T0

시장 지수는 원시 당일 반응이 시장 전체 상승에 의해 부풀려지는지 검증하는 데 사용한다.

### 9.3 시점 안전성

다음 조건을 충족한 사건만 기본 통계에 포함한다.

- 사건 원인문이 T0 종가 이전에 알려진 정보인지 확인 가능
- 사후 수정된 현재 원문을 과거 시점의 원문처럼 사용하지 않음
- 당시 주도주 목록을 보존함
- 현재 관련주 목록을 과거 사건에 적용하지 않음
- 해당 사건보다 미래에 발생한 뉴스나 가격 결과를 소재 분류에 사용하지 않음

`point_in_time_safe=false`인 사건을 별도 참고 분석에 사용할 수는 있지만 기본 TOP3와 조용히 섞지 않는다.

## 10. 소재 분류와 온톨로지 요구사항

이 기능은 소재 유형 정규화를 위해 얇은 Event Ontology가 필요하다. 그러나 실제 인포스탁 표본을 감사하기 전에 세부 통제어휘를 확정하지 않는다.

### 10.1 최소 필드 후보

```text
Theme
SubTheme
CatalystType
EventStage
ActorType
Actor
Project
Geography
BeneficiaryType
Direction
NoveltyType
PrimaryCatalystGroup
```

### 10.2 분류 예시

```text

```

### 10.3 필수 운영 규칙

- 같은 의미의 표현을 하나의 표준값으로 연결
- `UNKNOWN`, `OTHER`, `AMBIGUOUS` 허용
- 한 사건의 주 소재와 보조 소재 구분
- 상위·하위 소재가 TOP3에 동시에 중복 노출되지 않도록 표시 그룹을 상호 배타적으로 관리
- 새로운 소재 그룹의 생성·병합·분리 절차 정의
- 온톨로지와 분류 결과의 버전 보존
- LLM이 사용한 원문과 근거 span 보존
- 복합 사건을 하나의 소재로 억지 분류하지 않음

상세 통제어휘와 단계 관계는 별도 `event_ontology_design.md`에서 정의한다.

## 12. 순위 산식 초기안

최종 산식은 데이터 감사와 별도 방법론 검증 전 확정하지 않는다. 다음은 첫 비교 실험에 사용할 baseline이다.

### 12.1 순위 포함 조건

초기 가설:

- 서로 다른 중복 클러스터의 유효 사건 최소 5건
- 당시 주도주 전부가 종목코드와 연결됨
- 당시 주도주 전부의 T-1·T0 조정종가 존재
- `point_in_time_safe=true`
- `primary_catalyst_group`가 확정 또는 검수 승인됨
- 상승 방향 사건만 포함할지 상승·하락을 분리할지는 데이터 감사 후 확정

최소 5건은 확정값이 아니라 표본 분포를 보기 위한 초기값이다. 테마별 데이터가 지나치게 희소하면 임계값을 낮추기보다 기능을 숨기는 방안을 우선한다.

### 12.2 기본 정렬

```text
1차 정렬: 소재 유형별 사건 당일 반응 중앙값 내림차순
2차 정렬: 사건 당일 반응 25백분위 내림차순
3차 정렬: 유효 사건 수 내림차순
```

25백분위를 동률 기준에 넣는 이유는 일부 큰 사건만 강하고 나머지 사건은 약한 불안정한 그룹보다 반응이 비교적 일관된 그룹을 우선하기 위해서다.

### 12.3 시장 대비 반응 검증

종목별 시장 대비 반응 후보는 다음과 같다.

```text
종목 시장 대비 당일 반응(i, e)
= 종목 당일 반응(i, e) - 해당 종목 시장지수 당일 수익률(e)

사건 시장 대비 당일 반응(e)
= 당시 주도주들의 시장 대비 당일 반응 단순평균
```

최종 출시 전 다음 두 순위를 비교한다.

1. 원시 당일 반응 중앙값 순위
2. 시장 대비 당일 반응 중앙값 순위

두 결과가 자주 뒤집히면 원시 수익률만으로 `강한 반응`을 주장하지 않는다. 최종 사용자 지표와 표현은 별도 `historical_catalyst_ranking_methodology.md`에서 확정한다.

### 12.4 빈도의 역할

발생 횟수가 많다는 이유만으로 1위가 되지 않는다.

- 발생 횟수: 표본 신뢰성과 사용자 맥락
- 당일 중앙 반응: 초기 순위 기준
- 반응 분산: 안정성 검증

따라서 `자주 발생한 소재 TOP3`와 `반응이 컸던 소재 TOP3`를 혼합하지 않는다.

## 13. 중복·복합 사건 처리

### 13.1 중복 사건

다음은 하나의 사건 클러스터로 묶을 수 있다.

- 같은 날짜, 같은 프로젝트, 같은 단계의 문구 변형
- 여러 매체의 동일 발표 전재
- 인포스탁 원문의 경미한 수정

같은 사건 클러스터에서는 대표 사건 하나만 통계에 사용한다.

### 13.2 같은 날 여러 소재

한 거래일에 서로 다른 주요 소재가 동시에 발생하고 일봉 반응을 분리할 수 없으면 다음 중 하나로 처리한다.

1. 명확한 주 소재가 있으면 주 소재만 통계에 포함
2. 주 소재를 판단할 수 없으면 `COMPOSITE_EVENT`로 표시하고 TOP3 통계에서 제외

가격 반응 하나를 여러 소재의 성과로 중복 계산하지 않는다.

### 13.3 단계가 바뀐 동일 프로젝트

다음은 별도 사건으로 저장한다.

```text
수주 기대 → 최종후보 → 우선협상대상자 → 본계약
```

표시용 소재 그룹에서 함께 묶을지는 온톨로지 설계와 표본 수 감사 후 결정한다.

## 17. 품질 위험과 대응

### 17.1 인포스탁 선택편향

인포스탁 히스토리는 시장의 모든 뉴스가 아니라 이미 주목받은 사건을 중심으로 기록됐을 수 있다.

따라서 결과를 `이 소재가 나오면 평균적으로 오른다`고 해석하지 않고, `인포스탁에 기록된 과거 반응 사례 기준`이라고 표시한다.

### 17.2 인과관계 오인

같은 날 시장·업종·다른 뉴스가 함께 움직였을 수 있다. 가격 반응과 소재의 동시 관측은 완전한 인과 증명이 아니다.

시장 대비 수익률, 복합 사건 제외, 원문 근거 검수로 오인을 줄인다.

### 17.3 작은 표본

표본 1~2건의 큰 상승으로 TOP3가 만들어질 수 있다. 최소 표본 기준을 적용하고 유효 사건 수를 항상 함께 보여준다.

### 17.4 분류 수준 문제

`수주`처럼 너무 넓게 묶으면 의미가 없고 `체코 원전 우선협상자 선정`처럼 너무 좁게 묶으면 표본이 없다. 실제 데이터 분포를 보고 표시용 중간 수준을 정한다.

### 17.5 사후 정보 누수

사후에 수정된 인포스탁 원문이나 현재 종목 구성을 과거에 소급하면 순위가 왜곡된다. 원본 스냅샷, 관측 시각, 당시 주도주, 버전 이력을 보존한다.

### 17.6 한 사건의 중복 기여

한 사건을 `수주`, `유럽`, `정책` 등 여러 그룹에 중복 집계하면 상위 소재가 부풀려진다. TOP3 통계에는 주 소재 그룹 하나만 사용한다.

## 18. 검증 계획과 출시 게이트

### Gate 0. 원천 데이터 감사

- 대표 테마 5~10개 표본 수집
- 테마별 히스토리 수와 기간 확인
- 당시 주도주 코드 연결률 확인
- 원문 수정·중복·복합 사건 비율 확인
- T0 공개 시각 확인 가능 비율 확인

감사 결과로 신뢰 가능한 당일 반응을 만들 수 없으면 기능 구현을 중단하거나 표현을 변경한다.

### Gate 1. 소재 분류 품질

- 여러 테마와 연도를 포함한 300~500건 검수 세트 구축
- 최소 2인 독립 검수
- 주 소재 그룹 일치도 측정
- `UNKNOWN`, `AMBIGUOUS`, 복합 사건의 오분류율 확인
- LLM 분류와 간단한 규칙 baseline 비교

정확한 합격 기준은 검수 지침을 만든 뒤 사전 등록한다.

### Gate 2. 가격 계산 무결성

- 현재 관련주가 아니라 당시 주도주만 사용
- T-1·T0 거래일 처리 자동 테스트
- 기업행위 조정값 검증
- 일부 주도주만 존재할 때 사건 전체 제외
- 동일 사건 클러스터 중복 집계 방지

### Gate 3. 순위 안정성

- 중앙값 순위와 시장 대비 중앙값 순위 비교
- 최소 표본 3·5·10건 민감도 비교
- 특정 연도 하나를 제외했을 때 TOP3 변화 확인
- bootstrap으로 TOP3 포함 안정성 확인
- 한 사건 제거 시 순위가 과도하게 바뀌는지 확인

### Gate 4. 사용자 이해

사용자 테스트에서 다음을 확인한다.

- 오늘의 소재와 과거 TOP3를 구분하는가?
- TOP3를 미래 추천이나 상승확률로 오해하지 않는가?
- `당일 중앙 반응`과 `과거 N건`의 의미를 이해하는가?
- `오늘과 같은 유형`을 수익률 보장으로 해석하지 않는가?

오해가 크면 숫자를 줄이거나 상세 화면으로 이동하고 요약 화면에는 소재명만 제공한다.

## 20. 완료 조건

다음 조건을 모두 만족하면 기능 구현이 완료된 것으로 본다.

1. 인포스탁 과거 원문과 당시 주도주가 버전과 함께 저장된다.
2. 사건 중복과 복합 사건 처리 규칙이 자동 테스트된다.
3. 소재 유형이 온톨로지 버전과 근거 원문을 가진다.
4. 당시 주도주 T-1→T0 반응이 재현 가능하게 계산된다.
5. 현재 관련주를 과거 계산에 소급 사용하지 않는다.
6. 최소 표본과 품질 기준을 통과한 소재만 순위에 포함된다.
7. 세 개 미만이면 임의 항목으로 채우지 않는다.
8. 사용자가 집계에 포함된 과거 사건과 계산 기준을 확인할 수 있다.
9. `오늘과 같은 유형`은 동일 분류가 확인된 경우에만 표시된다.
10. 모든 화면에 과거 관측 요약이며 미래 예측이 아니라는 의미가 유지된다.

## 21. 아직 확정하지 않을 항목

다음은 실제 데이터 감사와 검증 문서에서 결정한다.

- 표시용 소재 유형의 정확한 세분화 수준
- 상승 사건만 포함할지 상승·하락을 분리할지
- 최소 유효 사건 수 3·5·10 중 최종값
- 원시 당일 반응과 시장 대비 반응 중 최종 순위 기준
- `오늘과 같은 유형`의 화면 노출 여부
- 요약 화면에 수익률 숫자를 직접 노출할지 여부
- 테마별 분류 체계를 얼마나 공통화할지 여부
- 인포스탁 외 뉴스·공시를 과거 소재 확정 근거로 추가할지 여부
