## 1. 서비스 완성의 의미

DAYJAVIEW는 장중 강해지는 국내 주식 테마를 찾고, 현재 움직임과 확산 정도, 주도주, 확인된 뉴스 근거를 보여주는 서비스다. 완성된 서비스는 여기에 다음 두 기능을 더한다.

1. 사용자가 자연어로 과거 시장·테마·종목·회사 사건을 질문할 수 있다.
2. 현재 사건과 의미상 관련된 과거 사례와 당시 실제 결과를 확인할 수 있다.

다음은 완성 범위가 아니다.

- 매수·매도 추천
- 자동매매
- 미래 상승 확률이나 예상 수익률
- 근거 없는 사건·숫자 생성
- 평가를 통과하지 않은 유사사례 공개

## 2. 최상위 진행 원칙

주 개발 순서는 다음 네 단계로 고정한다.

1. **온톨로지 v1 완성**
2. **자연어 질문 v1 완성**
3. **과거 반응 요약과 유사사례 완성**
4. **실시간·운영·접근성·장기 데이터 개선**

앞 단계가 다음 단계의 의미와 정확도를 결정한다. 따라서 화면부터 만들거나 LLM이 먼저 답하게 하지 않는다. 데이터 관계, 사람 검수, 결정론적 계산을 먼저 완성한다.

### 2.1 “완벽한 온톨로지”의 정의

절대적인 무오류나 끝없는 분류 개선을 뜻하지 않는다. 다음 조건을 만족한 **버전 고정 온톨로지 v1**을 뜻한다.

- 회사·종목·과거 사명·종목코드가 시점에 맞게 구분된다.
- 회사가 사건에서 맡은 역할과 그 근거 문장이 저장된다.
- 사건의 행동·대상·단계·상대방·지역·프로젝트·금액이 구조화된다.
- 같은 보도의 중복과 같은 프로젝트의 후속 단계가 구분된다.
- 테마 history와 DailyFeaturedTheme가 같은 사건 계약으로 연결된다.
- 사람 검수 표본으로 품질 기준을 통과한다.
- 같은 입력과 같은 버전은 항상 같은 결과를 만든다.
- 확신할 수 없는 연결은 추측하지 않고 미해결 또는 검수 대상으로 남긴다.

이 조건을 통과하면 v1을 고정하고 자연어 질문 단계로 이동한다. 이후 개선은 v1을 덮어쓰지 않고 새 버전으로 진행한다.

## 4. 1단계: 온톨로지 v1 완성

### 4.1 목표

자연어 질문과 유사사례가 공통으로 사용할 신뢰 가능한 사건 지식 구조를 완성한다.

### 4.2 포함 작업

1. **질문 계약과 검수 자료 완성 — E-22 단계 0**
   - 확정된 질의 17종의 ID, 필수 조건, 집계 단위를 기계 계약으로 고정한다.
   - 질문 해석 정답지, 답변 수치 대조 자료, 온톨로지 라벨 정답지를 완성한다.
   - AI 초안은 개발에만 사용한다. 출시 판정은 사람이 확인한 행만 사용한다.

2. **DailyFeaturedTheme 구조화 완성 — E-22 단계 1**
   - 부분 파싱 1,294건의 형식군을 감사한다.
   - 상세 문단, 종목별 상승·하락률, 관계, 근거 위치를 사건 mention으로 저장한다.
   - 거래일과 발행일을 구분한다.
   - Daily 전용 coverage·role·span 보고서를 만든다.

3. **회사 역할 연결 완성 — E-22 단계 3**
   - 회사가 실제 사건 주체인지, 단순 주도주인지, 수혜·피해 대상인지 구분한다.
   - 역할마다 원문 근거와 revision을 저장한다.
   - 과거 사명과 애매한 회사명은 유효기간과 검수 상태를 반영한다.

4. **사건 구조와 중복 제거 완성 — E-22 단계 4**
   - 현실 사건과 시장 반응을 다른 식별자로 저장한다.
   - 계약 기대, 입찰, 본계약, 납품, 취소를 별도 단계로 보존한다.
   - 상대방, 국가, 프로젝트, 금액, 통화를 구조화한다.
   - 같은 사건의 여러 기사·테마 기록은 한 번만 집계한다.
   - 같은 프로젝트의 후속 단계는 합치지 않고 관계로 연결한다.

### 4.3 완료 기준

사람이 확인한 표본만 사용해 다음 기준을 통과해야 한다.

| 항목 | 최소 기준 |
|---|---:|
| 코드 기반 회사 연결 precision | 100% |
| alias 자동 연결 precision | 99.5% |
| 회사 역할 precision | 95% |
| 핵심 역할 macro F1 | 90% |
| 사건 단계 정확도 | 90% |
| 금액·통화 exact match | 98% |
| 중복 병합 pair precision | 98% |
| 중복 병합 pair recall | 90% |
| 근거 span 유효성 | 100% |
| 사용자 답변 근거 coverage | 100% |
| 같은 artifact 재현성 | hash 일치 |

표본이 부족하거나 기준을 통과하지 못한 유형은 전체 단계를 막지 않는다. 해당 역할·질문만 잠그고, 검증된 범위만 다음 단계에 제공한다.

### 4.4 종료 산출물

- 버전이 고정된 회사·사건 온톨로지
- 사람이 확인한 gold set과 품질 보고서
- 회사·역할·사건·단계·프로젝트·금액 조회 모델
- 미해결 alias·낮은 confidence·중복 후보의 운영 검수 큐
- 자연어 질문이 읽을 수 있는 결정론적 repository

## 5. 2단계: 자연어 질문 v1 완성

### 5.1 목표

사용자가 `/research`의 입력창 하나에서 시장·테마·종목·회사·사건을 질문하고, 저장된 데이터와 근거만으로 답을 받게 한다.

### 5.2 포함 작업

1. **질문 해석 — E-22 단계 5**
   - 질문을 확정된 17종 중 하나로 분류한다.
   - 회사, 종목, 테마, 날짜, 기간, 역할, 사건 단계, 국가, 금액 조건을 해석한다.
   - 애매한 이름은 임의 선택하지 않고 후보를 제시한다.

2. **결정론적 답변 계산**
   - 질의 종류별 QueryPlan과 repository 함수를 만든다.
   - LLM이 숫자·순위·확률을 만들지 못하게 한다.
   - 같은 QueryPlan과 같은 데이터 버전은 같은 답을 반환한다.

3. **근거 중심 응답 계약**
   - 해석된 조건, 요약, 수치, 표본 수, 집계 단위, 근거 사건, 미제시 사유를 표시한다.
   - dataset·parser·어휘·query 버전을 모든 답변에 붙인다.
   - `질문 해석 실패`, `기록 없음`, `제품 범위 밖`, `품질 미검증`을 구분한다.

4. **리서치 화면 통합**
   - 공개 입력 표면은 자연어 입력 하나만 둔다.
   - 기존 `DAY_MOVERS` 읽기 기능은 QueryPlan에 흡수한다.
   - 날짜 선택형 `/movers` 화면과 공개 endpoint는 제거한다.
   - 질의 원문은 사용자 행동 분석 목적으로 저장하지 않는다.

5. **금액·실제 결과 질문 — E-22 단계 6**
   - 금액·통화·회사 귀속분을 중복 없이 계산한다.
   - 사건 이후 실제 주가를 2010년 이후 준비된 가격 자료에 연결한다.
   - 가격 누락은 0으로 바꾸지 않는다.
   - 2010년 이전 결과는 범위 밖 또는 데이터 없음으로 명시한다.

### 5.3 v1 범위

- v1은 정확도를 측정할 수 있는 닫힌 질의 17종을 제공한다.
- 관계를 자유롭게 이어 묻는 열린 질의는 v1 완료 조건이 아니다.
- 열린 질의는 온톨로지 단계 4, 질문 변환 검증, 근거 표시, 실패 시 17종 fallback 조건을 모두 충족한 뒤 별도 개방한다.
- 미래 예측, 추천, 목표가 질문은 계속 차단한다.

### 5.4 완료 기준

- 17종 각각의 질문 계약과 QueryPlan이 존재한다.
- 검증된 질문 유형은 실제 자연어 입력부터 근거 화면까지 끝까지 동작한다.
- 같은 입력은 같은 버전에서 같은 답을 반환한다.
- 질문 해석 실패와 기록 없음이 화면에서 구분된다.
- 상승과 하락 질문을 대칭으로 처리한다.
- 발행 전 “오늘”과 밀린 발행분의 거래일을 올바르게 처리한다.
- 모든 공개 답변이 근거 coverage 100%를 만족한다.

## 6. 3단계: 과거 반응 요약과 유사사례 완성

### 6.1 과거 테마 반응 소재 TOP3 — E-18

유사사례 검색 전에 온톨로지가 과거 반응 집계에도 유효한지 확인한다.

- 테마별 과거 소재 유형을 실제 반응 중앙값으로 정렬한다.
- 최대 3개만 표시한다.
- 표본 수와 데이터 기간을 함께 표시한다.
- 미래 예측이나 현재 사건의 예상 수익률로 표현하지 않는다.

### 6.2 유사사례 검색 엔진과 평가 — E-19

- M-TXT, 온톨로지, 혼합 검색을 같은 조건에서 비교한다.
- 사건 당시 알 수 있던 정보만 검색 특징으로 사용한다.
- 미래 가격은 사례 선택이 끝난 뒤 결과 표시용으로만 연결한다.
- 회사·역할·단계·프로젝트 특징을 후보 검색에 추가한다.
- 두 사람의 독립 블라인드 평가로 관련성을 검증한다.
- 새 봉인 기간으로 최종 평가한다.

### 6.3 사용자 화면과 자연어 연결 — E-20, E-22 단계 7

- 평가를 통과한 고정 버전만 production registry에 올린다.
- 승인되지 않은 결과와 변경 가능한 `latest`는 API가 읽지 않는다.
- 당시 주도주, T+1·T+5·T+20 실제 결과, 표본 범위, 누락 사유를 표시한다.
- 자연어 질문에서 유사사례를 요청하면 같은 승인 버전을 사용한다.
- 낮은 confidence와 미해결 회사 연결은 운영 검수로 보낸다.

### 6.4 완료 기준

- 2인 블라인드와 새 봉인 기간 평가를 통과한다.
- 선택 과정에 미래 정보가 들어가지 않았음이 테스트로 고정된다.
- 승인된 immutable artifact만 서비스된다.
- 유사사례와 당시 실제 결과를 명확히 분리해 표시한다.
- 게이트 실패 시 화면과 자연어 답변이 모두 잠긴다.

## 7. 4단계: 나머지 완성 작업

온톨로지, 자연어 질문, 유사사례가 끝난 뒤 다음 작업을 진행한다.

1. **A-3 실제 장중 시세 최종 검증**
   - 실시간 순위, 재연결, 거래일 전환, 장 마감까지 확인한다.

2. **C-13 테마 상세·근거 실시간 갱신**
   - 상세 화면을 열어 둔 동안 수치와 근거가 멈추지 않게 한다.

3. **실제 장중 기준선 축적**
   - 20거래일 이상 쌓아 거래대금 배수와 관심 공백을 정식 값으로 전환한다.
