# DAYJAVIEW 실시간 테마 트리맵 구현 계획

## 1. 완료 결과

`인사이트` 화면에서 다음 기능이 동작하면 완료다.

1. 트리맵은 상승률 단일 기준으로 표시하며 지표 토글을 두지 않는다.
2. 상승률은 기존 상한형 유동시총 가중 테마 수익률을 사용한다.
3. 서버가 받은 실제 체결로만 숫자·색상·면적·위치가 변한다.
4. 숫자와 색상은 500ms 단위, 레이아웃은 최대 1초 단위로 반영한다.
5. 테마 블록을 누르면 기존 테마 상세 화면으로 이동한다.
6. 연결 지연·Coverage 부족·장 마감 상태를 잘못된 0으로 표시하지 않는다.

현재 `docs/dayjaview-mockup.html`의 랜덤 데이터는 시연용이다. 운영 코드에 포함하지 않는다.

## 3. 지표 계산

### 3.1 상승률

새 산식을 만들지 않는다. `product_decisions.md`의 PD-001과 `realtime_theme_feature_spec.md` 13.2를 그대로 사용한다.

```text
유동시가총액_i
= 전일 조정종가_i × 상장주식수_i × 유동주식비율_i

종목 등락률_i(t)
= 현재가_i(t) ÷ 전일 조정종가_i - 1

기본 가중치_i
= 유동시가총액_i ÷ Σ 유동시가총액

종목당 가중치 상한
= max(30%, 1 ÷ 유효 Core 종목 수)

테마 수익률(t)
= Σ(상한 적용 가중치_i × 종목 등락률_i(t))
```

적용 규칙:

- `Core` 종목만 사용한다.
- 가중치는 전일 기준으로 장중 고정한다.
- 상한 초과분은 상한 미도달 종목에 기존 비중대로 재배분한다.
- Core Coverage 80% 미만 또는 유효 Core 종목 2개 미만이면 트리맵에서 제외한다.
- 화면 값은 백분율로 표시한다. 내부 복합 순위 점수는 사용하지 않는다.

## 4. 데이터 처리 구조

기존 실시간 계산 흐름을 유지한다.

```text
키움 0B 체결
→ stock_realtime_state 갱신
→ stock_theme_index로 영향받는 테마 조회
→ 해당 테마만 dirty 표시
→ 500ms마다 dirty 테마 지표 재계산
→ 메모리의 theme_realtime_metrics 갱신
→ 변경 시 즉시 다음 500ms 전송 주기에 스냅샷 전송
→ 변경이 없어도 2초마다 최신 상태 스냅샷 전송
```

금지:

- 체결마다 전체 테마를 재계산하지 않는다.
- 스냅샷을 만들 때 DB를 조회하지 않는다.
- 사용자별로 테마 지표를 다시 계산하지 않는다.
- 트리맵 전용 저장 테이블을 만들지 않는다.

### 4.1 서버 후보 선택

한 번의 스냅샷에는 Coverage를 통과한 상승률 상위 12개만 포함한다.

### 4.2 전송 방식

- 앱의 기존 WebSocket 연결을 재사용한다.
- `인사이트` 진입 시 `theme_treemap` topic을 구독한다.
- 화면 이탈 시 topic만 구독 해제한다.
- 별도 WebSocket 연결을 만들지 않는다.
- 스냅샷은 모든 필드를 포함한 전체 스냅샷으로 보낸다. 클라이언트 delta 병합은 만들지 않는다.
- 스냅샷마다 증가하는 `sequence`를 넣는다. 클라이언트는 이전 sequence를 무시한다.
- 재연결 후 즉시 전체 스냅샷 1개를 보낸다.
- 값이 바뀌면 다음 500ms 주기에 전송하고, 값이 그대로여도 freshness 확인을 위해 2초마다 전송한다.

### 4.3 전송 계약

```json
{
  "type": "theme_treemap_snapshot",
  "sequence": 8421,
  "asOf": "2026-08-13T10:18:22.500+09:00",
  "marketPhase": "REGULAR",
  "dataStatus": "LIVE",
  "themes": [
    {
      "themeId": "theme_nuclear_export",
      "eventId": "evt_20260813_0012",
      "displayName": "원전수출",
      "weightedReturn": 0.027,
      "coreCoverage": 0.91,
      "qualityFlags": []
    }
  ]
}
```

필드 규칙:

- 비율은 퍼센트 문자열이 아닌 소수 원값으로 보낸다. `0.027`은 `2.7%`다.
- 계산할 수 없는 값은 `0`이 아니라 `null`이다.
- `dataStatus`: `LIVE | DELAYED | CLOSED`
- `qualityFlags`는 기존 계산 엔진의 플래그만 전달한다.

## 5. 프런트엔드 구성

다음 네 단위만 만든다.

1. `treemapStream`
   - topic 구독·해제
   - sequence 검사
   - 마지막 정상 스냅샷 보관
   - 지연 상태 판정
2. `selectTreemapItems`
   - 상승률 필터
   - 값 내림차순 정렬
   - 상위 12개 선택
   - 레이아웃 입력값 생성
3. `ThemeTreemap`
   - 사각형 계산
   - keyed DOM 갱신
   - 색상·라벨·애니메이션
4. `InsightScreen`
   - 상태 문구
   - 상세 이동

전역 상태 저장소를 추가하지 않는다. 인사이트 화면 생명주기에 종속된 상태로 유지한다.

### 5.1 레이아웃

- 직접 분할 알고리즘을 작성하지 않는다.
- 프로젝트에 트리맵 구현이 없으면 `d3-hierarchy`의 `treemapSquarify`만 사용한다.
- 전체 D3 렌더링은 사용하지 않는다. 사각형 좌표 계산만 맡긴다.
- 노드 key는 `themeId`다.
- 상승률 면적 입력값은 `weightedReturn` 원값이다.
- 임의 가중치, 랜덤값, 복합 순위 점수를 면적에 넣지 않는다.

### 5.2 색상

`weightedReturn`으로 결정한다.

```text
색상 강도 = min(|weightedReturn| ÷ 5%, 1)
```

- `+0.1%` 초과: 중립색에서 상승색으로 보간
- `-0.1%` 미만: 중립색에서 하락색으로 보간
- `-0.1% ~ +0.1%`: 중립색
- 색상만으로 값을 전달하지 않고 숫자를 함께 표시한다.

### 5.3 라벨

| 블록 크기 | 표시 |
|---|---|
| 110×70px 이상 | 테마명 + 상승률 |
| 70×48px 이상 | 테마명 + 상승률 |
| 그 미만 | 테마명만 표시하거나 텍스트 숨김 |

텍스트가 숨겨져도 버튼의 `aria-label`에는 테마명과 상승률을 넣는다.

### 5.4 갱신과 애니메이션

- 500ms 안에 여러 스냅샷이 오면 최신 스냅샷만 적용한다.
- 숫자와 색상은 최신 스냅샷 적용 시 갱신한다.
- 레이아웃 계산은 최대 1초에 한 번만 실행한다.
- 사각형 이동과 크기 변화는 700ms CSS transition으로 처리한다.
- 값이 변하지 않으면 레이아웃과 애니메이션을 실행하지 않는다.
- DOM을 매번 비우고 다시 만들지 않는다. `themeId` 기준으로 기존 노드를 갱신한다.
- `prefers-reduced-motion`에서는 transition을 제거한다.

### 5.5 상호작용

- 블록 전체를 `<button>` 또는 기존 라우터의 링크로 만든다.
- 클릭·Enter·Space로 동일하게 테마 상세로 이동한다.
- `themeId`와 `eventId`를 기존 테마 상세 화면에 전달한다.

## 7. 구현 순서와 단계별 검증

### 1단계. 기존 계산 결과 확인

작업:

- `theme_realtime_metrics`에서 `weighted_return`과 Core Coverage를 읽을 수 있게 한다.
- 기존 계산 산식을 수정하지 않는다.

검증:

- 같은 시각의 기존 홈 계산 결과와 트리맵 입력값이 일치한다.
- DB 조회 없이 메모리 상태에서 스냅샷을 만들 수 있다.

### 2단계. 서버 스냅샷 빌더

작업:

- Coverage 필터를 적용한다.
- 상승률 상위 12개를 만든다.
- 전송 계약에 맞춰 직렬화한다.

검증:

- 결과가 최대 12개다.
- 계산 불가 값이 `null`이다.
- 입력 상태가 같으면 출력도 같다.

### 3단계. 기존 WebSocket에 topic 추가

작업:

- `theme_treemap` 구독·해제를 추가한다.
- 값이 바뀌면 다음 500ms 주기에, 바뀌지 않으면 2초마다 전체 스냅샷을 broadcast한다.
- sequence와 재연결 전체 스냅샷을 구현한다.

검증:

- 화면에 들어간 클라이언트만 스냅샷을 받는다.
- 값 변화가 없을 때 전송 주기가 2초보다 짧아지지 않는다.
- 재연결 후 delta 없이 정상 상태가 복구된다.

### 4단계. 순수 선택·레이아웃 함수

작업:

- 상승률 필터·정렬·상위 12개 선택 함수를 만든다.
- `d3-hierarchy`로 좌표를 계산한다.

검증:

- 결과에 0% 이하 테마가 없다.
- 모든 사각형이 컨테이너 안에 있고 겹치지 않는다.
- 같은 입력은 같은 좌표를 만든다.

### 5단계. 화면 렌더링

작업:

- 트리맵·상태 문구를 연결한다.
- keyed DOM 갱신과 CSS transition을 적용한다.
- 기존 상세 화면 이동을 연결한다.

검증:

- 타일 값·면적·색상이 상승률 규칙과 일치한다.
- 타일 클릭과 키보드 조작이 같은 상세 화면으로 이동한다.
- 작은 화면에서 가로 스크롤이 생기지 않는다.

### 6단계. 실시간·저하 상태

작업:

- 500ms coalescing, 1초 레이아웃 제한, stale 판정을 연결한다.
- `DELAYED`, `CLOSED` 처리를 연결한다.

검증:

- 값이 없는 상태를 0으로 표시하지 않는다.
- 연결이 끊기면 마지막 정상 화면을 유지한다.
- 장 마감 후 블록이 움직이지 않는다.
- 변경이 없는 스냅샷에서 애니메이션이 실행되지 않는다.

### 7단계. 목업과 문서 정리

작업:

- `docs/dayjaview-mockup.html`에서 지표 토글과 보조 지표 문구를 제거한다.
- 트리맵을 상승률 단일 기준으로 고정한다.
- 랜덤 시뮬레이터는 목업 전용 함수 하나로 격리하고 운영 코드와 공유하지 않는다.
- 승인된 규칙을 화면 구조 문서와 제품 결정 문서에 반영한다.

검증:

- 목업과 계획서의 값 형식·상태 문구가 일치한다.
- 트리맵을 복수 지표로 설명하는 문구가 남아 있지 않다.

## 8. 필수 테스트

### 서버 단위 테스트

- 상승률 후보 필터와 정렬
- Coverage 미달 제외
- `null` 직렬화
- sequence 증가
- 변경 없음 상태의 2초 전송 주기

### 프런트엔드 단위 테스트

- 상위 12개 선택
- 색상 강도 계산
- 오래된 sequence 무시
- stale 판정
- 라벨 단계 판정

### 통합 테스트

1. 저장된 0B 체결 fixture를 재생한다.
2. 영향받는 테마만 계산되는지 확인한다.
3. 스냅샷이 화면까지 전달되는지 확인한다.
4. 실제 값 변화와 타일 숫자·색상·면적 변화를 비교한다.
5. 연결을 끊고 재연결해 전체 상태가 복구되는지 확인한다.
6. 테마 타일에서 상세 화면으로 이동하는지 확인한다.

### 성능 테스트

- 180종목 구독 fixture를 30분 재생한다.
- 0B 수신부터 화면 숫자 반영까지 P95 1초 이내다.
- 레이아웃 계산은 초당 1회를 넘지 않는다.
- 타일 DOM 노드는 최대 12개를 유지한다.
- 30분 후 메모리와 DOM 노드 수가 계속 증가하지 않는다.
- 트리맵 갱신 때문에 100ms 이상 메인 스레드 작업이 반복되지 않는다.

## 9. 완료 조건

- [ ] 상승률이 기존 서버 산식과 일치한다.
- [ ] 실제 체결이 없으면 타일이 움직이지 않는다.
- [ ] 정상 연결에서 체결 후 1초 이내 숫자가 반영된다.
- [ ] 레이아웃은 최대 초당 1회 갱신된다.
- [ ] Coverage 부족과 수신 지연을 0으로 표시하지 않는다.
- [ ] 지표 토글이 없다.
- [ ] 클릭과 키보드로 기존 테마 상세에 이동한다.
- [ ] 재연결과 장 마감 상태가 정상 동작한다.
- [ ] 단위·통합·30분 성능 테스트가 통과한다.
